**3. 本轮确定的实施取舍**

- T01 的收件箱存放在 MySQL，只保存内容引用与排序字段，使用数据库唯一约束完成入箱幂等。
- 内容发布事务同时写入内容 Outbox 和两类持久化任务。索引 Worker 与扇出 Worker 从 MySQL 领取任务。这个首轮方案复用现有 MySQL；任务状态、接管与批次提交都可以在本地事务中检查。RabbitMQ 继续承载当前投票异步链路，T01 不扩大其通用化改造范围。
- T01、T02 的 HTTP 默认 Feed 沿用拉模式与现有历史可见性。显式 `mode=push` 提供分发联调入口。T02 独立完成历史补齐、关注竞争和删除；后续 T02B 实现服务端混合读取时，再明确存量准备和默认入口切换协议。保留拉模式对照。
- 新发布内容的 HTTP 成功边界是内容与 Outbox/任务共同提交。列表索引和粉丝收件箱异步可见。鉴权仍沿用 Redis Session，发布路径的调整不宣称消除了整个接口的 Redis 依赖。
- 点赞迁移安排在 T03。目标输入收敛为点赞/取消的目标状态。旧 `-1/0/1` 记录、在途事件、单调版本和重建策略要一起设计，T01 延续现有投票语义。

**4. 后续任务的目标与验收方向**

T02 需要把“新关注可看到历史内容”延续到推模式。补齐任务必须持久化并分批推进，定义新关注与同时发帖之间的覆盖关系。重复关注维持幂等，取关后读取立即按当前关系过滤，重新关注后的旧任务不能破坏新关系。本人删除采用必要的软删除与权限检查，删除状态先约束读取，异步清理负责空间与索引维护。删除、编辑需要的失效事件通过 T01 的事件基础扩展，避免建立独立的临时定时器补偿体系。

T02B 实现普通作者推、高扇出作者拉的混合读取。发布时的路由决定可恢复，两个来源按同一时间/ID 边界合并、去重与过滤；作者策略双向切换不漏历史或在途内容。实现不以本地负载不足为由取消；测量用于理解写放大、读合并和阈值的代价。明确范围见 `FEED_HYBRID_PLAN.md`，详规基于 T02 实际模型后续编写。

T03 要先写出迁移顺序，再实现点赞接口与本人状态查询。需要区分旧负票的存量转换、迁移边界之前已产生的事件，以及之后的新点赞请求；保留版本单调性。点赞是否受现有七天窗口限制，应明确选择并实现。热榜可以采用固定时间窗口，但时间窗口与用户是否允许取消点赞是两项不同规则。热度与缓存查询统一使用已确定的点赞解释。

T04 选择一套稳定的发布时间与 ID 顺序，游标绑定必要的分类和排序上下文。复用 `community`，保持旧入口兼容或给出迁移说明。有序 ID 与详情、作者、分类、点赞数据分别批量读取，再按 ID 关联。失效条目过滤后补取必须有扫描预算，游标推进不能反复返回同一段无效数据。

T05 仅依赖真实存在的发布时间和点赞数据，定义时间窗口、更新周期、Top-N 上限、同分次序和可由 MySQL/投票状态重算的来源。有限榜单按批次生成，游标携带榜单版本与位置，过期明确要求刷新。同批次固定 ID 顺序，内容可见性仍实时检查。需要在现有分类交集缓存与独立分类索引之间做一次取舍，避免同时维护多套等价路径。

T06 在 T04 装配入口上增加批量详情缓存、缺失部分批量回源、TTL 与热点请求合并。编辑/删除的失效以可靠事件补偿，说明并发回填和 TTL 的边界。动态点赞数与个人状态独立读取，共享缓存不携带用户私有状态。依赖有超时预算，回源有并发上限及明确的忙碌响应；这些保护属于本轮读取路径。进程内 singleflight 的作用范围要准确说明。

**5. 本阶段暂缓范围**

受控死信回放、全链路积压背压安排到后续主线。在线无停机重建另行立项。推拉混合与高粉阈值已按用户最新补充列入 T02B，本轮 T02 不提前实现。评论、收藏、图片/对象存储、视频、搜索、AI、通知、作者主页、个性化推荐、微服务和新组件均不进入本阶段。

分发任务所必需的 Outbox、重试、幂等、接管、分批进度，以及读取所必需的超时和有限回源，随相关功能实现。全面故障治理、专项性能优化及用户的系统压测与故障排查教学安排到后期。必要正确性检查由实现方和开发会话完成。

**6. 每轮交付与接力规则**

1. 网页端只实现本轮详细任务书，返回增量补丁、完整实现、迁移和实际检查记录。
2. 开发会话基于真实代码执行构建、相关回归与关键正确性检查。环境不支持的检查标注待验收，不用旧阶段的通过结果替代。
3. 简单 Bug 由开发会话直接处理；较大改动整理成下一份修复任务。完成验收后，再以集成后的代码生成下一轮输入。
4. 用户继续承担转交材料与按节奏学习的角色。任务书准备完成不代表对应功能完成，历史性能数字也不代表新版本收益。
5. 每轮保留输入基线、增量补丁、设计取舍、复跑配置与实际检查结果，供用户后期亲手完成发现瓶颈、定位、优化和同条件复测。已知 Bug 在交付中修复，学习对照采用已归档的版本与真实结果。
