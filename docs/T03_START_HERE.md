## 优先方式：GitHub 连接器读取文本，执行容器离线运行

网页端此前能够通过 GitHub 连接器读文件，但执行容器不能解析 GitHub 域名。这是两种访问通道，不要在容器里重试 clone、curl 或 requests 取源码，也不要因附件未挂载而只返回设计方案。

1. 用 GitHub 连接器从本轮固定交接提交读取 `docs/TASK_T03_LIKE_MIGRATION.md`、本文件、清单，以及 `docs/handoff/t03_offline_bootstrap.py` 的完整文本。
2. 将脚本文本用代码/文件工具写到 `/mnt/data/t03_offline_bootstrap.py`。它是 37573 字节 ASCII 文件；如文本工具截断，按行范围分段读取并保持所有 Base64 行完整，不以省略号代替。
3. 核对脚本 SHA-256：`e4cf14f27886ae169afd2921a3d79b2e0c55404ac0d88e631a72ae1632e128ac`。不符则修正文本，不运行受损脚本。
4. 执行 `python3 /mnt/data/t03_offline_bootstrap.py`。脚本会在有限目录范围内查找现存 T02 源码，也可明确传 `--source /实际上轮实现目录`。输出默认是 `/mnt/data/convo-t03-offline`。

6. 成功应为 `status=verified`、上述源码身份和 `source_files=180`；保存旁边的 `convo-t03-offline-input-report.json`，然后在新目录真正实现 T03。

本地输入提交是合成的，SHA 可以不同于上游实现基线；内容符合清单即可，不要求在离线容器恢复整个上游历史。相对 `t03-input` 生成补丁。任务书可直接通过连接器阅读，不必位于脚本生成的代码目录内。

脚本不能从空气生成全部不变源码。如果上轮 T02 目录已经不存在，应准确报告“现有源码缺失”，并通过连接器取得固定版本缺失文件或真正挂载完整源码；不能把无网络和无源码混为一谈。未知修改先在副本核对，不覆盖旧目录。

## 其他可用方式

具备真实 Git 网络的环境可以 checkout 本轮固定交接提交，按清单核对应用文件。完整输入包 `convo-t03-input.zip` 也提供备用，但它能在本机打开不等于网页执行容器能读附件。执行容器有网络时才能使用 clone，不能据此替代上述离线链路。

完整 Git 输入比清单多六个旧主机/编辑配置和本轮交接说明，属于有意差异。离线快照中省略这些文件不是删除指令。用户本地部署配置及产品路线文档不进入源码交接。
