## API 与消息证据

注册三名用户，经发布接口发布两帖，另植入一篇 30 天历史样本。关注后 pull/push 三篇集合与顺序相同；点赞、重复点赞、取消、重复取消及旧入口让版本按真实变化推进 1/2/3/4/5，MySQL 最终 1:v5。15 次状态读取不增加写计数；A/B 账户隔离、非法/超限批量、字符串 ID、已删除内容、共享缓存与新旧入口共用 10 次额度均核对。

旧 stale/same_version 事件被确认；旧高版本、新同版本冲突和新负方向三类事件进入 DLQ，业务状态保持不变。临时移走测试库去重表制造真实消费失败，已接受点赞进入 retry，恢复后经 TTL 返回主队列并最终持久化。短暂取消专用 DLQ 绑定时，发布收到 mandatory return，原投递保留；恢复绑定后同一事件进入 DLQ。相关变动仅作用测试资源并已恢复。

排空测试结合真实 Redis 与本地 HTTP 样本，覆盖主队列 unacked、retry、DLQ 非零，HTTP 失败、非法 JSON、缺计数字段及 XLEN=0 但 PEL=1；均拒绝继续。管理端不可达和实际 Stream 非空同样由维护 CLI 拒绝。
